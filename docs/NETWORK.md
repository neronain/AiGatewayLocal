# พอร์ตและโปรโตคอลที่ LiteGate ใช้

เขียนไว้เพราะคำถามนี้มาถึงตอนที่สายเน็ตเดินไปแล้ว — ไฟร์วอลล์ของโรงเรียนตั้งเสร็จ
เครื่องอยู่หลัง NAT และคนที่ต้องเปิดพอร์ตให้ ไม่ใช่คนเดียวกับคนที่ติดตั้งระบบ

> ทุกพอร์ตในนี้ **ตั้งค่าได้** ตัวเลขที่เขียนคือค่าเริ่มต้น ไม่ใช่ข้อบังคับ

---

## ขาเข้า — ที่ต้องเปิดให้คนอื่นเข้ามาถึง

| พอร์ต | โปรโตคอล | ใครเรียก | จำเป็นไหม |
|---|---|---|---|
| **8080/tcp** | HTTP | ผู้ใช้ทุกคน · Claude Code · Codex · SDK · คอนโซล | **ใช่ — พอร์ตเดียวที่ต้องเปิด** |

ทุกอย่างของ LiteGate อยู่บนพอร์ตเดียว:

```
/                    หน้าต้อนรับ (เบราว์เซอร์) · JSON (script)
/console/            คอนโซลผู้ดูแล
/console/member/     หน้าตรวจสิทธิ์ของสมาชิก
/v1/...              OpenAI + Anthropic API
/healthz  /readyz    สำหรับ load balancer และ monitoring
/metrics             Prometheus
/docs                OpenAPI
```

เปลี่ยนพอร์ตด้วย `GW_PORT` · ผูกกับอินเทอร์เฟซเดียวด้วย `GW_HOST`
(ค่าเริ่มต้น `0.0.0.0` = รับทุกอินเทอร์เฟซ)

**ไม่มี TLS ในตัว** — ถ้าต้อง HTTPS ให้วาง reverse proxy (nginx / Caddy / Traefik)
ไว้หน้า แล้วให้มันคุยกับ LiteGate ทาง HTTP ภายในเครื่อง

---

## ขาออก — ที่ LiteGate ต้องต่อออกไปได้

| ปลายทาง | พอร์ต | เมื่อไร |
|---|---|---|
| เครื่องที่รันโมเดล (vLLM / llama.cpp / Ollama / SGLang) | ตามที่ตั้งไว้ · มัก **8000–8099/tcp** | ทุกคำขอ |
| ผู้ให้บริการออนไลน์ (Gemini, MiniMax, OpenRouter, …) | **443/tcp** | เฉพาะเมื่อเพิ่ม backend แบบคลาวด์ |
| Redis | **6379/tcp** | เฉพาะเมื่อตั้ง `GW_REDIS_URL` |
| PostgreSQL | **5432/tcp** | เฉพาะเมื่อตั้ง `GW_DATABASE_URL` เป็น Postgres |
| LMDS hub | **8600/tcp** | เฉพาะเมื่อเปิดปุ่ม "แก้ให้เลย" ที่คุยกับ LMDS |

ค่าเริ่มต้นใช้ **SQLite ในไฟล์** และ **ไม่ใช้ Redis** — ติดตั้งพื้นฐานจึงไม่ต้องเปิด
พอร์ตขาออกอะไรเลยนอกจากไปหาเครื่องที่รันโมเดล

> ไซต์ที่ไม่มีทางออกอินเทอร์เน็ตใช้งานได้ครบ ตราบใดที่ไม่ได้เพิ่ม backend แบบคลาวด์ ·
> หน้าเว็บทุกหน้าไม่ดึงฟอนต์หรือสคริปต์จากภายนอกเลย (มีเทสต์คุมไว้)

## ถ้าใช้ port forward หรืออยู่หลัง reverse proxy

รูปแบบที่เจอบ่อย: เครื่องเกตเวย์อยู่ในวงภายใน แล้ว forward พอร์ตจาก router
หรือวาง proxy ไว้หน้า

**สิ่งที่ทำงานได้เลย ไม่ต้องตั้งอะไรเพิ่ม**

* คอนโซลและหน้าสมาชิก — ใช้ที่อยู่แบบสัมพัทธ์ทั้งหมด ย้ายไปอยู่หลัง path ไหนก็ได้
* ทุก endpoint ของ API
* ตัวอย่าง `curl` บนหน้าแรก — สร้างจากที่อยู่ที่เบราว์เซอร์เห็นจริง ไม่ใช่ที่เซิร์ฟเวอร์คิดเอง

**สิ่งที่ต้องรู้**

* ชุดทดสอบที่สั่งจากคอนโซลยิงกลับมาที่ตัวเองผ่าน `127.0.0.1:<GW_PORT>` **โดยเจตนา** —
  ไม่ได้เดาที่อยู่จากคำขอที่เข้ามา เพราะเบราว์เซอร์อาจมาทาง proxy หรือชื่อโดเมนภายนอก
  ที่ตัวเซิร์ฟเวอร์เองไม่รู้จัก · แปลว่าชุดทดสอบใช้ได้แม้อยู่หลัง forward
* ถ้า proxy ตัดหรือเขียนทับ header ให้ปล่อยผ่านอย่างน้อย `Authorization`, `x-api-key`
  และ `accept` — ไม่งั้นการยืนยันตัวตนจะพัง
* ถ้าใช้ SSE/streaming ต้อง **ปิด buffering** ที่ proxy ไม่งั้นคำตอบจะมาทีเดียวตอนจบ
  (nginx: `proxy_buffering off;`)
* timeout ของ proxy ต้องยาวพอสำหรับคำตอบยาว — 60 วินาทีมักไม่พอ แนะนำ 600 ขึ้นไป

ตัวอย่าง nginx ที่ใช้ได้จริง:

```nginx
location / {
    proxy_pass         http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header   Host $host;
    proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_buffering    off;          # จำเป็นสำหรับ streaming
    proxy_read_timeout 600s;
}
```

## ตรวจว่าเปิดถูกไหม

```bash
curl -s http://<เกตเวย์>:8080/healthz          # ต้องได้ status: ok
curl -s http://<เกตเวย์>:8080/ | head -c 80    # script ได้ JSON
```

จากเครื่องเกตเวย์ ตรวจว่าไปถึงเครื่องที่รันโมเดลได้:

```bash
curl -s http://<เครื่องโมเดล>:8000/v1/models | head -c 200
```
